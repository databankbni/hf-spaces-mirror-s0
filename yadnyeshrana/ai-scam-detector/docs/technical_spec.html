1. Executive Summary & Brand Identity

The AI Scam Detector is a secure, state-of-the-art system designed to protect individuals from financial cyber-scams directly over WhatsApp. Supported by a conversion-optimized landing page, a secure dashboard, and a robust admin control panel, the ecosystem aims to prevent UPI frauds, job scams, and phishing attacks before they occur.

2. Product Features & Capability Map

The platform operates across three main integrated layers: the Automated WhatsApp Bot, the Web Landing Page and User Dashboard, and the Admin Control Suite.

A. WhatsApp Bot Layer

  • Link & URL Analysis: Extracts URLs from messages and checks them against OpenPhish blacklists.
  • PDF & Screenshot Scanner: Users can upload or forward images/PDFs. The bot uses Gemini 2.5 Flash Vision to analyze visual markers (e.g. fake electricity letters or QR code "Receive" cash scams).
  • Contextual Thread Replies: Binds outgoing replies to the user's specific forwarded message using Meta Context API.

B. Web Funnel & History Layer

  • Free Scanner Card: Permits anonymous users to run 1 free scan on the web every 24 hours (enforced via IP rate limits).
  • Conversion Bridge: Automatically prefills phone numbers and triggers checkout modals when redirected from WhatsApp commands.
  • Secure History Timeline: Paid users request OTP codes via WhatsApp to log in and decrypt their historical scans list.

C. Admin Control Panel

  • Interactive Charts: Visualizes daily scans and scam distribution statistics using Chart.js.
  • Kill Switch & Controls: Includes quick toggles to pause bot listening or edit heuristic regex rules in real time.
  • Test Users (QA Whitelist): Admin dashboard tool to add or delete whitelisted phone numbers, granting them unlimited scans bypass.

Hugging Face container spaces enforce strict egress firewalls blocking direct outbound connections to graph.facebook.com and api.telegram.org. To resolve this egress blockade, the server utilizes a custom proxy server topology:

Outbound Messaging: Outgoing WhatsApp replies and Telegram admin notifications are relayed to the Google Apps Script Web App (passing credentials as query parameters). The proxy fetches the destination API via Google's firewall-free network.

Binary File Downloads: Because Meta's media CDN endpoints (e.g. lookaside.fbsbx.com) are hosted outside the restricted API domains, the Hugging Face container bypasses the proxy to download images and PDFs directly. This prevents string encoding corruption and ensures 100% file integrity.

Platform Rationale & Choice Justifications

Each component in this platform topology was selected to optimize performance, minimize operational costs (targeting a true $0/month hosting bill), and bypass container firewall constraints:

  • Hugging Face Spaces (Hosting): Selected over alternatives like Render or Heroku because it offers a permanently active, free Docker-ready container hosting environment that does not go to sleep after periods of inactivity. This prevents cold start delay lags on incoming WhatsApp webhook messages.
  • Meta Developer Dashboard (WhatsApp API): Leverages the direct official WhatsApp Cloud API rather than high-cost resellers (like Twilio or Gupshup). This yields the fastest delivery latency, supports native context replies, and avoids message markup fees.
  • Google Apps Script (Egress Tunnel): Used as a serverless, zero-cost proxy to bypass Hugging Face's container-level firewall which blocks direct egress connections to api.telegram.org and graph.facebook.com. It routes requests via Google's whitelisted serverless CDN.
  • Firebase Realtime Database (Data Store): Provides a hierarchical, ultra-low latency NoSQL key-value store. Its free tier covers up to 10GB of storage and millions of read/write actions, making it ideal for tracking real-time API quotas and whitelists.
  • Razorpay (Payment Gateway): Offers deep UPI mobile application intent integrations for the Indian market, enabling seamless checkout redirects from WhatsApp parameters to active local UPI wallets.

Monitoring & Keep-Alive Systems

  • Telegram Alert Bot: Used for instant out-of-band system logging and security auditing notifications. Configured via TELEGRAM_BOT_TOKEN and TELEGRAM_CHAT_ID. When critical events occur (such as Meta API token expiration code 190, Razorpay payment signature verification failures, or high-confidence user-submitted crowdsourced scam reports), the server formats a clean HTML notification and dispatches it immediately to the administrator's Telegram chat via the Google Apps Script proxy.
  • UptimeRobot Integration: Implements a 24/7 automated keep-alive system. By pinging the Express server's /health status endpoint once every 5 minutes, UptimeRobot ensures that the Hugging Face container remains awake, prevents routing latency on incoming WhatsApp webhook pulses, and provides immediate email/SMS warnings if the container encounters downtime.

5. Webhook Resiliency & Concurrency Controls

To safeguard against server floods, duplicate payments, and API outages, the bot implements several core limits:

FIFO Concurrency Queue
Max 3 tasks per user

Incoming messages are serialized sequentially. Spammers exceeding the queue limit get instantly rejected.

OTP rate limiting
1 req/3 mins per phone

Caps IP verification requests (max 3/hour per IP) to prevent wallet-drain attacks.

Gemini API Failover
3-try retry with fallbacks

Retries transient connections, falling back to local heuristics if Gemini is offline.

6. Security & Privacy Safeguards

To maintain user privacy, comply with data guidelines, and prevent system vulnerabilities, the platform enforces the following protocols:

  • PII Hashing: User phone numbers are converted to secure SHA-256 hashes before being saved in logs, preventing plain-text phone exposures.
  • Log Encryption: Checked messages and threat text elements are encrypted via AES-256-CBC symmetric encryption before writing to database collections.
  • Redirect URL Resolver: Shortened links (like bit.ly) are followed up to 3 hops via HTTP HEAD redirects to resolve and blacklist final destination domains.
  • Memory Leaks Sweep: An automated background sweep daemon runs hourly in the container, deleting visitor rate-limit IP records older than 24 hours.
  • Silent Log Fault Tolerance: Database history checks logging is isolated inside independent try-catch blocks. A database crash never blocks sending scan reports to users.

7. Free-Tier Optimization & Scaling Safeguards

To operate a production-ready system indefinitely within the free tiers of Hugging Face, Gemini 2.5 Flash, and the Firebase Spark plan, the platform employs several architectural optimizations:

  • Cloudflare Workers Egress Proxy: Routes the custom domain aiscamdetector.in to Hugging Face space containers for free (bypassing the $9/month HF Pro requirement). The worker dynamically rewrites virtual host headers and modifies location redirects in real-time.
  • Real-Time Sync Caching: Maintains a persistent database sync cache via a single WebSocket .on('value') listener on startup, reducing subsequent scan lookup read queries to exactly zero network costs.
  • Transactional Batch Operations: Group up to 40 scraped OpenPhish threat intelligence links in a single transactional database update (utilizing client-side generated push keys) to avoid duplicate network transfers and listener trigger recursion.
  • Twin In-Memory Caching: Intercepts incoming scans using a 1-hour TTL Gemini analysis cache (composite SHA-256 hashed keys) and a 6-hour TTL URL redirect resolution cache to prevent redundant API/network overhead.
  • Outbound warning rate-limiting: Cooldown maps restrict daily quota warnings to once every 4 hours per user, preventing message loops and saving Meta WhatsApp outbound messaging credits.
  • Post-Sanitization Validation: Enforces strict phone parameter presence checks after digits-only normalization to prevent empty string queries from leaking into database lookups.
