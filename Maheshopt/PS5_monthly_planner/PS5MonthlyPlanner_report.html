PS5 Monthly Planner — Technical Report

This report describes the implementation of the PS5 Monthly Planner project, including architecture, scraping logic, Gradio UI wiring, data persistence, and important code details.

Project Overview

The project uses Gradio for a browser-based UI and BeautifulSoup for scraping PlayStation release data from psindex.co.uk. The app loads monthly PS5 release listings, shows them in a paginated table, allows game selection, and generates a planner with daily playtime estimates.

Main Files

  • PS5MonthlyPlanner.py: application implementation and scraper logic
  • planner_memory.json: persisted planner history saved between runs

Dependencies

  • gradio: UI framework
  • beautifulsoup4: HTML parsing
  • requests optional, used if installed; otherwise urllib is used
  • json, datetime, re, os, time

Data Persistence

Memory file

The file planner_memory.json stores saved planner entries and the most recent planner selection. The loader gracefully handles invalid JSON and creates a backup when the file is corrupted.

def load_memory():
    if os.path.exists(MEMORY_FILE):
        try:
            with open(MEMORY_FILE, "r", encoding="utf-8") as f:
                return json.load(f)
        except json.JSONDecodeError as e:
            print(f"Warning: could not parse {MEMORY_FILE}: {e}. Resetting saved history.")

save_memory() uses json.dump(..., default=str) so non-serializable objects like datetime.date can be saved safely.

Fetching Remote HTML

The function fetch_url_text() provides resilient page retrieval:

  • Prefer requests.get() when available
  • Fallback to urllib.request.urlopen()
  • Use browser-like headers to avoid blocking
  • Cache responses for up to 600 seconds
  • Retry on 429 Too Many Requests with exponential backoff

Release Date Parsing

Release dates are normalized into Python datetime.date using parse_release_date(). It supports:

  • YYYY-MM-DD
  • DD Month YYYY
  • DD Month plus default year
  • TBA, TBD, and UNKNOWN as future dates

Scraping Monthly Game Releases

The heart of the scraper is fetch_games(month, year):

  • Builds primary and calendar URLs for the selected month
  • Tries page selectors in order: div.min-w-0.space-y-2, div.space-y-2, and article
  • Extracts title text from either visible link text or aria-label
  • Ignores placeholder entries like View game or View editions
  • Removes duplicate game URLs
  • Extracts date text from paragraph or nested elements, with a regex fallback
  • Sorts results by release date and title

Planner Generation

generate_planner() builds the monthly plan and computes the daily hour goal.

Daily hours formula

days = (first day of next month) - (first day of current month)
daily_hours = round(game.get("hours", 40) / days, 2)

For December, it correctly wraps to January of the next year.

The function also saves the planner to history and updates the past planner dropdown.

Pagination and Filtering

  • render_games_page() displays 12 games per page
  • load_monthly_games() fetches and stores games in LAST_GAMES
  • change_games_page() moves between pages
  • filter_game_choices() filters dropdown entries based on the search textbox

UI Wiring with Gradio

The app uses a gr.Blocks() layout consisting of:

  • Month and year dropdowns
  • Load Games button
  • HTML display panel for the game list
  • Search textbox + game selector
  • Generate Planner button
  • Cover image and game info panels
  • Planner HTML output
  • Past planner dropdown and load button

Callback wiring is implemented with .click() and .change() handlers.

Important Implementation Details

  • Global state: LAST_GAMES stores currently loaded games for detail display.
  • History safety: invalid JSON is backed up and reset automatically.
  • Date serialization: planner saves use default=str so datetime.date does not break JSON.
  • Fallback scraping: if the page structure changes, the scraper tries multiple selectors.

How the App Works End-to-End

  1. User selects month/year and clicks Load Games.
  2. App calls fetch_games() and parses the PS Index release page.
  3. Games load into the HTML table and dropdown.
  4. User can filter games using the search box.
  5. User selects a game and clicks Generate Planner.
  6. App computes daily hours and returns the planner HTML.
  7. Planner is saved to planner_memory.json for later retrieval.

Conclusion

This project is a compact web-based PS5 release planner built around scraping, UI state, and history persistence. It is designed to remain robust against page structure changes and to store user planner output safely.
