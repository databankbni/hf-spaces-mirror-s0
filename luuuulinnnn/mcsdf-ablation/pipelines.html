📐 共享主干:DL3DV 81帧 → VGGT 一致几何(+Umeyama 对齐)→ 前 18 帧点云 → warp splat 到 81 个目标位姿 → z_mem(VAE latent)+ knownness k(density 覆盖率,[F,30,52] 每 token)→ 条件注入 + τ(k) 噪声调度 → per-token 扩散(Wan 14B + per-token AdaLN)→ 81 帧输出

① 核心:knownness map → noise map 的四种翻译函数

τ = 每个 token 的起始噪声(它这辈子见过的最高噪声)。x 轴 = k(被看清的程度),y 轴 = τ。

Ⓐ 无映射(uniform / plain)

baseline r128(均值匹配 uniform)· expG0(标准训练,全员纯噪起步,内容全靠通道)· 老 VACE-ft benchmark 赢家同款

Ⓑ 宽带 + 0.45 地板(早期)

expA / expB 推理配置。问题:known token 从 0.45 起步 → 跳过高噪段 → 纹理死(P-SDEdit 证明)

Ⓒ 宽带 + 0.85 clamp(expC~F/G 现役)

expC / expE 三兄弟 / expE_sync / expF / expF_sync / expG。纹理保住了(0.85 够高),但 k 的连续信息浪费

Ⓓ 窄带线性(expJ,新)

expJ_narrow / expJ_ray。k 不再兑换"跳过开头",只兑换"早一点结束"(配 sync 日历 = 完工时刻表)

② 采样日历:τ 决定的时序如何展开

legacy:错峰起跑 · 同时到终

问题:known 冻结期"只广播不倾听",unseen 做结构决策时看到的是半噪 splat

SYNC(expH,已验证 +0.23dB)

unseen 后半程对着 GT 级邻居做决策;每一步 known 都严格更干净

SYNC + 窄带(expJ)= 完工时刻表

看得越清 → 完工越早 → 给后面的人当锚;k 的连续排序第一次被日历完整使用
